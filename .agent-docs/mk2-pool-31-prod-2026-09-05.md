# MK2 prod — pool VLAN100 `192.168.31.1/24`

Fecha: **2026-09-05**

Amplía capacidad de altas FIBER en MK2: el pool `192.168.30.1/24` (~241 IPs asignables, octetos 10–250) se agota. Se habilita un segundo `/24` en el mismo uplink VLAN 100.

## Inventario

| Pieza | Valor |
|-------|--------|
| Router | MK2 / CCR 2 (`network_device.id=8`, `38.224.231.4`) |
| Interfaz | `vlan100-olt` (VLAN 100 tagged desde 2026-09-10) |
| Gateway | `192.168.31.1/24` |
| `ip_pool.ip_segment` | `192.168.31.1/24` (id **163**) |
| `host_device_id` | `8` |
| `is_eligible` | **`1`** desde 2026-09-10; el `.30` (id 8) pasó a `0` |
| Rango backend | `.10`–`.250` (~241 IPs) |
| Pool previo | `192.168.30.1/24` (id 8) **ya no elegible** — gateway MK2 se mantiene para abonados existentes |

Switch aplicado: [mk2-pool-31-eligible-switch-2026-09-10.md](./mk2-pool-31-eligible-switch-2026-09-10.md)

## Orden operativo (obligatorio)

1. **RouterOS MK2** — aplicar [`scripts/mikrotik-mk2-pool-31.rsc`](../scripts/mikrotik-mk2-pool-31.rsc) (gateway + NAT srcnat).
2. **Deploy Core** — WAR con `SubscriptionVlanRules` que acepta prefijos `192.168.30.` y `192.168.31.` en VLAN 100.
3. **MySQL prod** — ejecutar [`scripts/sql/ip-pool-mk2-vlan100-31-seed.sql`](../scripts/sql/ip-pool-mk2-vlan100-31-seed.sql).

No activar el pool en BD antes del deploy: `IpAllocationService` podría asignar `.31` y `assertPoolAligned` rechazaría el alta.

No usar `POST /ip-pool` (hardcodea `interface=LAN`); preferir SQL + RSC.

## Verificación

```text
# MK2
/ip address print where address~"192.168.3[01]"
/ping 192.168.31.1 count=2

# MySQL prod
SELECT id, ip_segment, host_device_id, is_eligible FROM ip_pool
WHERE is_eligible = b'1' ORDER BY id;

# Alta de prueba: IP debe poder caer en 192.168.31.10–250 cuando .30 esté lleno
```
